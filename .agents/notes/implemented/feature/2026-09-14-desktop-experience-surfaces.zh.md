# Agent Note: 桌面端的恢复、更新、首次启动与诊断

Status: implemented

[English](2026-09-14-desktop-experience-surfaces.md) | 中文

这些界面属于[采用的上游应用](../architecture/2026-09-13-adopt-upstream-desktop.zh.md)。

## 问题

采用后的应用交付了本 fork 路线图要求的恢复、更新、首次启动与诊断这四个界面，但对它服务的那类用户——没有终端、没有包管理器、也没有 Node.js 的用户——每一个都还不完整。失败页只说启动失败，对三个操作不加解释，因此两个会改动 profile 的操作看起来和重启一样安全。被拒绝的更新可能在之后一次重新检查失败时被遗忘，下载失败或重启交接失败则是无声的。已安装应用的首次启动对自带的运行时以及插件管理位置只字未提。管理窗口则没有任何地方可以读到支持请求所需的版本与路径。本记录说明每个界面现在承诺什么、其状态存放在哪里，以及为什么每个都构建在桌面壳里。

## 决策

### 恢复页说明失败并限制 profile 操作

本地加载页渲染来自主进程的失败文本，并解释每个恢复操作的作用，而不仅仅给它一个标签。重启始终提供；禁用第三方插件和重置 Desktop 仅在已初始化应用能够修复其 profile 时提供，而这依赖已打包的应用资源，因此开发项目和早期初始化失败只提供重启。两个会修改 profile 的操作以危险样式呈现，并各自带有一条说明——禁用保留插件文件并在不加载它们的情况下启动，重置删除桌面端配置和第三方插件且不保留备份——点击某个操作会进入忙碌状态、禁用全部操作，随后在页面原位报告它自己的失败，而不是让文本保持不变。当桌面壳资源或 preload 失败导致页面本身无法加载时，一个独立文档会携带相同的失败文本，始终提供重启，且仅在具备 profile 恢复能力时才提供这两个 profile 操作。

### 更新保留被拒绝的版本并报告每次失败

一次检查会把它的阶段发布到每个窗口，并保留可用版本。原生确认框会指明该版本，并说明此版本包含配套的 dsh 运行时、应用将在安装完成后重新启动，因此用户在确认前就能看到该版本和这次重启。拒绝会让该版本继续保持已知，因此之后无法访问更新源的检查会在保留版本旁边报告错误，而不是替换它，该版本也仍可安装。接受会等待正在进行的检查，然后下载并验证该版本；下载失败会得到报告，并让该版本仍可重试。下载成功后，应用会停止 dsh 子进程并把安装与重启交给 electron-updater，交接失败同样会得到报告：应用继续以旧版本运行，而更新仍可安装。

### 首次启动是基于 Electron 自有状态的原生对话框

未找到 profile 而启动的已安装应用会在工作区打开后显示一次原生指引，说明它自带的运行时、该运行时的位置以及插件的管理位置。该指引由 Electron 主进程状态驱动，而不是客户端包，因为它要为一次工作区可能尚未打开的首次启动发声，而且桌面壳本就拥有 locale 载荷和 profile 的周边状态。它的“不再显示”选择写到 `$DSH_HOME/desktop/` 下、profile 旁边，因此能挺过 profile 重置；启动时已存在 profile 的，或任何开发项目，都不会显示该指引。

### 诊断位于管理窗口

管理窗口新增一个“诊断信息”区块，列出应用版本和 dsh 版本、Harness 主目录、运行时位置，以及上次启动的结果，并提供一个复制组装后文本块的操作，以及一个显示 Harness 主目录的操作。该文本块在主进程中由主进程事实与本地化标签一次性组装，因此渲染进程只渲染一个载荷、复制到的正是它显示的内容、不读取文件系统、也不调用 shell；它暂时无法读取的版本会显示为不可用，而不是让该区块失败。这些事实被加入本就在拥有 profile、且本就带有 preload、locale 载荷和菜单入口的那个窗口，而不是加入一个为了五行只读内容就要复制这套接线的第二个窗口。

## 考虑过的替代方案

- **由客户端包显示首次启动指引。** 否决：该指引存在的意义是已安装应用的首次启动，那时渲染进程自身的界面尚不可信；而客户端包还要为渲染桌面壳本就已本地化的文案新增路由、桥接和持久化存储。原生对话框使用主进程拥有的状态与 locale，且 profile 旁边的单个文件能挺过重置，而 profile 内部的客户端存储做不到。
- **为诊断另开一个窗口。** 否决：管理窗口本就拥有 profile，且本就带有 preload、locale 载荷和菜单入口，因此安装事实应属于那个本就代表安装的界面。第二个窗口要为五行只读内容复制这一整套接线，并访问同一个 `$DSH_HOME`。
- **在重新检查失败时遗忘被拒绝的版本。** 否决：之后更新源停止响应时，被拒绝的版本正是用户需要的事实；遗忘它会把一次临时的检查失败变成“没有可用更新”。保留它能让“安装”在那之后仍可触达，而这正是曾经确认过该版本的意义。
- **在任何失败中都提供全部恢复操作。** 否决：禁用插件和重置 Desktop 会改动 profile，因此在本就无法用已打包资源修复它、或尚不存在 profile 的地方提供这些操作，等于给出无法执行的动作。以 profile 恢复能力作为门槛能让页面保持诚实，而重启是每个上下文都能执行的那一个操作。

## 后果

失败页现在会说明失败原因并解释每个操作，其会修改 profile 的操作只在能够执行时出现，因此无法修复 profile 的上下文不再提供会失败的操作；忙碌状态意味着缓慢的恢复不再让页面看起来毫无变化。被拒绝的更新能在一次失败的重新检查之后保持可安装，下载失败或重启交接失败会得到报告而非无声。首次启动指引会介绍一次自带运行时和插件窗口，其确认记录存放在 profile 旁边，因此重置后应用重新回来时，不会重复用户已经关闭过的指引。诊断把支持请求所需的版本与路径变成一个可复制的文本块，在主进程中组装，渲染进程不访问文件系统。

代价正是这些选择所指明的：该指引是原生对话框，因此使用桌面壳的文案、无法随应用一起定制样式；被保留的被拒绝版本可能在更新源停止响应后仍被提供，错误文本必须对此作出解释；诊断文本块镜像本地化标签，因此新增一项事实要在两套词典中同步添加，并由该区块的测试覆盖。
