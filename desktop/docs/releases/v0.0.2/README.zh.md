# 桌面版 v0.0.2

[English](README.md) | 中文

Status: Proposed

DeepSeek Harness 的第二个桌面版本：仍然是同一个已签名、自包含的 macOS 应用，但可以在运行期间安装与卸载插件。

## 本版本要成立的事

用户无需等待新版本发布，就能为已安装的应用增加能力，也能把它再拿掉。

具体而言，在应用运行期间：

- 插件面板列出已安装的插件、正在运行的插件，以及启动失败的插件。
- 从磁盘选择、或从 URL 获取的插件包，无需终端、无需重启应用即可安装。
- 插件提供的工具在安装完成后立即可以被 agent 调用。
- 停用插件会移除其工具；启用会恢复。
- 卸载插件会删除它的文件与记录，且不影响会话与设置。
- 插件崩溃、卡死或无法启动，既不影响应用，也不影响其他插件。
- 已安装的插件在应用更新后依然存在，因为它在应用包体之外。

## 本版本不包含

| 不包含 | 原因与后续 |
|---|---|
| 需要本应用不携带的运行时（`python`、`uv`）的插件包 | 应用不带 Python 运行时。安装时即拒绝并说明原因，而不是装上去、之后才失败。 |
| 插件的交互式配置（`user_config`） | 在安装时收集配置值需要一套独立的设置界面。需要它的包会被拒绝，而不是装上一份半配置的副本。 |
| 插件目录 / 插件市场 | 目前从文件或 URL 安装。发现机制需要一套本版本尚不具备的发布流程。 |
| 桥接 MCP 的 Resources 与 Prompts | MCP 客户端目前桥接工具；另两项能力在 harness 中还没有消费者。 |
| 在 harness 进程内运行插件代码 | 插件是独立程序。它能贡献的只限于进程边界能承载的东西——目前是它的工具。 |
| 发布者身份验证 | 不校验签名。界面会在安装前说明插件是外部程序。 |
| 应用内更新 | 与 v0.0.1 相同：更新源已发布，但应用尚未消费它。它是一个独立的改动；它与本特性都改动启动路径。 |

## 改动范围

| 区域 | 改动 | 归属 |
|---|---|---|
| 插件存储 | 新增：包校验、安装、已安装注册表，以及运行期挂载/卸载 | `desktop/packages/plugin-store` |
| 插件面板 | 新增：Web Settings 中的「已安装」标签页，驱动存储自己的路由 | `desktop/packages/ui-plugin-store` |
| 选择插件包 | shell 应答面板发起的文件对话框请求 | `desktop/apps/shell` |
| 组合 | 两行组合项，以及把插件包加入闭包 manifest | `desktop/packages/bundle-desktop-app`、`desktop/runtime-closure` |
| 挂载外部服务器 | 原样复用 | `packages/mcp/mcp-client` |

没有任何东西被安装进已签名的应用，闭包自身的内容仍与从前一样在构建时固定。

## 如何观察完成

1. 在应用运行期间，从面板安装一个包，其工具在下一轮对话中即可调用。
2. 停用该插件后这些工具消失；启用后恢复。
3. 卸载后 `$DSH_HOME/plugins/<id>` 与注册表条目一并删除。
4. 服务器立即退出的包被记录为「启动失败」，原因显示在面板中，应用继续运行。
5. 杀掉已挂载插件的服务器进程后应用不受影响；存储会重连，面板显示中断。
6. 更新应用后已安装的插件仍然存在。
7. 产物仍然是从一个 DMG 里拖出一个应用即可安装：没有新增首次启动步骤，也没有新增文件数量。
